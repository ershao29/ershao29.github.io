连接服务器并设置项目环境

本页记录首次安装步骤。amd128 已有可用环境时，直接使用末尾的激活入口。安装集中在 /home/ps/jishaobin/research-field-NTE，通过当前 shell 中的脚本启用环境。

ssh amd128
bash --noprofile --norc
cd /home/ps/jishaobin/research-field-NTE
mkdir -p downloads envs .cache .tmp

cat > env-local.sh <<'EOF'
export NTE_ROOT=/home/ps/jishaobin/research-field-NTE
export CONDARC="$NTE_ROOT/condarc-local.yml"
export CONDA_PKGS_DIRS="$NTE_ROOT/.cache/conda-pkgs"
export CONDA_ENVS_PATH="$NTE_ROOT/envs"
export CONDA_REGISTER_ENVS=false
export XDG_CACHE_HOME="$NTE_ROOT/.cache"
export PIP_CACHE_DIR="$NTE_ROOT/.cache/pip"
export MPLCONFIGDIR="$NTE_ROOT/.cache/matplotlib"
export CUDA_CACHE_PATH="$NTE_ROOT/.cache/cuda"
export TORCH_HOME="$NTE_ROOT/.cache/torch"
export TMPDIR="$NTE_ROOT/.tmp"
export PYTHONNOUSERSITE=1
export PIP_CONFIG_FILE=/dev/null
export PIP_USER=0
export MPLBACKEND=Agg
unset PYTHONPATH PYTHONHOME PIP_TARGET PIP_PREFIX
EOF

cat > condarc-local.yml <<'EOF'
channels:
  - conda-forge
channel_priority: strict
auto_activate_base: false
register_envs: false
EOF

source ./env-local.sh
mkdir -p "$CONDA_PKGS_DIRS" "$PIP_CACHE_DIR" \
  "$MPLCONFIGDIR" "$CUDA_CACHE_PATH" "$TORCH_HOME"

CONDA_REGISTER_ENVS=false 关闭用户级环境登记。PIP_CONFIG_FILE=/dev/null 关闭 pip 配置文件读取，所以安装命令显式指定 pip 索引。Conda channels 和 pip index 是两套独立配置。当前环境在这个 shell 中持续有效，执行 exit 可退出子 shell。

安装 Miniforge 与 Python 3.10

首次安装下载 Linux x86_64 安装包和校验文件。使用 -b 批量安装，再加载项目内的 conda.sh。已有 miniforge3/ 时从 source 开始。

cd "$NTE_ROOT/downloads"
curl -fL --retry 3 -O \
  https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-Linux-x86_64.sh
curl -fL --retry 3 -O \
  https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-Linux-x86_64.sh.sha256

sha256sum -c Miniforge3-Linux-x86_64.sh.sha256

校验显示 OK 后，安装管理器和项目环境。保存安装包及校验文件可记录实际安装版本。

bash Miniforge3-Linux-x86_64.sh -b -p "$NTE_ROOT/miniforge3"
source "$NTE_ROOT/miniforge3/etc/profile.d/conda.sh"

conda create -y \
  --prefix "$NTE_ROOT/envs/deepsdf" \
  --override-channels -c conda-forge \
  python=3.10 pip

conda activate "$NTE_ROOT/envs/deepsdf"
which python

Python 应位于 /home/ps/jishaobin/research-field-NTE/envs/deepsdf/bin/python。Miniforge 的 base Python 与项目环境 Python 可以是不同版本。Miniforge 安装说明

安装 GPU 版 PyTorch

验证过的版本为 torch==2.5.1+cu124，运行库为 CUDA 12.4，服务器驱动 560.35.05 可以支持。nvidia-smi 中的 CUDA 版本反映驱动支持能力。本教程使用 wheel 提供的运行依赖，训练阶段可以直接调用 GPU。

通过 PyTorch 官方 cu124 索引安装时使用以下命令。这个索引列出的部分 NVIDIA 依赖曾在 amd128 连接超时。PyTorch 官方版本命令

python -m pip install torch==2.5.1 \
  --index-url https://download.pytorch.org/whl/cu124

使用本地 wheel 和镜像补齐依赖

本次部署手动上传了 PyTorch 和 NVRTC wheel。下面命令直接读取这两个文件，再从清华镜像安装其余依赖。cp310 对应 Python 3.10，+cu124 对应 CUDA 12.4 构建。

wheel_dir="$NTE_ROOT/downloads"
python -m pip install \
  "$wheel_dir/torch-2.5.1+cu124-cp310-cp310-linux_x86_64.whl" \
  "$wheel_dir/nvidia_cuda_nvrtc_cu12-12.4.127-py3-none-manylinux2014_x86_64.whl" \
  --index-url https://pypi.tuna.tsinghua.edu.cn/simple \
  --timeout 60

可把索引改成 https://pypi.org/simple。指定的本地 wheel 决定 PyTorch 版本，索引用于补齐依赖。CUDA Runtime、cuDNN、cuBLAS 等仍可能下载超过 2 GB。下载缓慢时参见索引和 tmux 记录。

获取仓库并安装 Python 依赖

amd128 已有两个仓库。新目录可执行克隆命令；已有目录可直接安装依赖。本指南的兼容补丁基于 DeepSDF 上游提交 48c19b8。

cd "$NTE_ROOT"
git clone --recursive https://github.com/facebookresearch/DeepSDF.git
git clone https://github.com/mkofler96/SdfSampler.git
cat > "$NTE_ROOT/constraints-deepsdf.txt" <<'EOF'
numpy==1.26.4
scipy==1.11.4
scikit-image==0.22.0
matplotlib==3.8.4
plyfile==1.0.3
torch==2.5.1
EOF

python -m pip install \
  -c "$NTE_ROOT/constraints-deepsdf.txt" \
  numpy scipy scikit-image matplotlib plyfile trimesh==5.2.0 \
  --index-url https://pypi.tuna.tsinghua.edu.cn/simple

python -m pip install \
  -c "$NTE_ROOT/constraints-deepsdf.txt" \
  -e "$NTE_ROOT/SdfSampler" \
  --index-url https://pypi.tuna.tsinghua.edu.cn/simple

python -m pip check

DeepSDF 当前仓库通过目录导入运行，进入 DeepSDF/ 后执行 Python 脚本。CMake 工程编译的是原版网格采样器 PreprocessMesh 和 SampleVisibleMeshSurface。本流程由 Python SdfSampler 产生样本，训练与 PLY 导出可直接运行。要使用原版网格预处理，再按官方说明准备 CLI11、Pangolin、nanoflann 和 Eigen3，并运行 cmake 构建。DeepSDF 官方仓库

应用兼容补丁

下载兼容补丁并上传到 $NTE_ROOT/downloads/。对干净的上游代码先检查再应用。当前服务器已经有这些修复，可通过 git diff 查看。

cd "$NTE_ROOT/DeepSDF"
git apply --check "$NTE_ROOT/downloads/deepsdf-cu124-compatibility.patch"
git apply "$NTE_ROOT/downloads/deepsdf-cu124-compatibility.patch"
git diff --check
  • deep_sdf/data.py 把正负样本转为 float32，与网络参数类型一致。
  • deep_sdf/mesh.py 使用整数网格索引和 marching_cubes API。
  • generate_training_meshes.py 将潜向量移动到解码器所在设备。
  • 训练恢复与网格导出涉及的 torch.load 显式使用 weights_only=True。

这份补丁对应五个文件。已有部分修复的代码和其他分支，应阅读补丁后逐项合并。

保存激活入口并验证 GPU

cat > "$NTE_ROOT/activate-deepsdf.sh" <<'EOF'
source /home/ps/jishaobin/research-field-NTE/env-local.sh
source "$NTE_ROOT/miniforge3/etc/profile.d/conda.sh"
conda activate "$NTE_ROOT/envs/deepsdf"
cd "$NTE_ROOT/DeepSDF"
EOF

source "$NTE_ROOT/activate-deepsdf.sh"

python - <<'PY'
import torch
import deep_sdf
from SdfSampler.sdf_sampler import SDFSampler

print("PyTorch:", torch.__version__)
print("CUDA runtime:", torch.version.cuda)
assert torch.cuda.is_available()
print("GPU:", torch.cuda.get_device_name(0))

x = torch.randn(128, 128, device="cuda", requires_grad=True)
(x @ x).square().mean().backward()
torch.cuda.synchronize()
print("GPU forward/backward OK")
PY

预期输出包含 2.5.1+cu124、12.4 和 RTX 3090。若导入时出现 nvJitLink 符号错误，见运行库路径排查。后续 SSH 登录后执行激活脚本即可，也可保存依赖记录。

source /home/ps/jishaobin/research-field-NTE/activate-deepsdf.sh

mkdir -p "$NTE_ROOT/environment-records"
python -m pip freeze > "$NTE_ROOT/environment-records/deepsdf-pip.txt"
conda list --explicit > "$NTE_ROOT/environment-records/deepsdf-conda-explicit.txt"
