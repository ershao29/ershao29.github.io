下载源、超时与下载速度

本地 PyTorch wheel 被读取后，pip 会继续处理声明的依赖。NVRTC、CUDA Runtime、cuDNN 和 cuBLAS 是不同的包，上传一个 wheel 后仍需要其余依赖。

本次部署涉及的三个索引
索引作用与观察
download.pytorch.org/whl/cu124提供 PyTorch cu124 构建；部分 NVIDIA 文件指向 pypi.nvidia.com
pypi.org/simple公共 Python 索引，可补齐本地 PyTorch wheel 的依赖
pypi.tuna.tsinghua.edu.cn/simple清华 PyPI 镜像，相同 cuBLAS 文件在本次 IPv6 测速中更快

2026-11-12 的短时测速中，官方 PyPI 约 29 kB/s，清华 IPv6 约 1.7 MB/s。IPv4 曾连接超时。这些数字反映当时网络状态；索引页可访问，还需验证实际 wheel 文件的下载连接。

ping baidu.com 检查到百度的 ICMP 连通性，pip 访问的是文件服务器的 HTTPS 连接。Conda 环境激活后，命令行 --index-url 仍决定本次 pip 索引。Conda channels 配置只管理 Conda 包。

wheel_dir="$NTE_ROOT/downloads"
python -m pip install \
  "$wheel_dir/torch-2.5.1+cu124-cp310-cp310-linux_x86_64.whl" \
  "$wheel_dir/nvidia_cuda_nvrtc_cu12-12.4.127-py3-none-manylinux2014_x86_64.whl" \
  --index-url https://pypi.tuna.tsinghua.edu.cn/simple \
  --timeout 60

确认开头 Looking in indexes 显示预期索引。指定本地 +cu124 wheel 后，索引用于获取剩余依赖。+cpu wheel 无法用于本教程直接调用 .cuda() 的训练。pip 配置说明 · 清华镜像用法

用 tmux 持续下载和训练

服务器已安装 tmux。在普通 SSH 终端运行的 pip，可先按 Ctrl+C 取消，再进入新会话重新执行。缓存可复用；下载到一半的文件能否续传取决于下载状态和服务器支持。

tmux new -s deepsdf-download 'bash --noprofile --norc'

source /home/ps/jishaobin/research-field-NTE/activate-deepsdf.sh
# 在会话中执行 pip 命令或训练命令。

按 Ctrl+b，松开后按 d 分离会话。断开 SSH 后任务继续运行。重新登录后恢复。

tmux attach -t deepsdf-download

训练中的 PyTorch 警告

torch.load 的 weights_only 提醒

PyTorch 2.5.1 提醒未来将更改加载默认值。本实验的模型、潜向量、优化器与日志由字典、张量和基本类型组成，相关入口已显式使用 weights_only=True，并用真实检查点验证恢复。

data = torch.load(full_filename, weights_only=True)

这些修复位于 train_deep_sdf.py、deep_sdf/workspace.py 和 generate_training_meshes.py。

Using -1 to represent CPU tensor is deprecated

旧版 DeepSDF 把潜向量留在 CPU、解码器放在 GPU，并用 DataParallel 分发输入。反向传播把潜向量梯度传回 CPU 时，PyTorch 2.5.1 内部仍使用 -1 标识 CPU，触发 FutureWarning。当前组合可继续训练，解码器仍在 GPU 计算；这条警告保留在实测记录中。

nvJitLink 运行库路径

服务器当前的 env-local.sh 额外设置了 NVIDIA wheel 的 nvJitLink 库目录。若导入 PyTorch 时遇到 libcusparse 或 __nvJitLink... 的 undefined symbol，应核对依赖版本及库搜索顺序，再在项目 shell 中将匹配的 wheel 库目录放到前面。

export LD_LIBRARY_PATH="$NTE_ROOT/envs/deepsdf/lib/python3.10/site-packages/nvidia/nvjitlink/lib:$LD_LIBRARY_PATH"
python -c 'import torch; print(torch.__version__, torch.version.cuda)'

这项设置在当前 shell 及子进程中生效。参考脚本下载保留了服务器现有的这一设置。

网格导出与续训检查

  • 没有零面。 第 2 轮曾全部预测为正，先继续训练，检查 SDF 范围是否跨零。
  • marching_cubes_lewiner 不存在。 scikit-image 0.22 使用 marching_cubes API。
  • CPU/CUDA 设备不一致。 原导出路径通过 latent_vector.to(device) 将潜向量移到解码器设备。
  • 网格坐标异常。 用整数索引 y = (index // N) % N 和 x = index // (N * N)。
  • 缺少归一化参数。 本球体数据使用归一化坐标，原版导出添加 --keep_normalization。
  • 恢复后没有继续训练。 检查 NumEpochs 是否大于恢复轮数，原始 train_demo.py 会把它写回 2。
  • 数据或批次为空。 检查 DataSource、TrainSplit 和实际样本。原训练器使用 drop_last=True，ScenesPerBatch 应不超过训练实例数量。

具体修复见兼容补丁，导出操作见三维可视化。
